# Стратегический Роадмап внедрения Data Mesh (Future 2.0)

В данном документе представлен план трансформации управления данными от монолитного DWH к децентрализованной модели Data Mesh.

## 1. Этапы Внедрения

### Фаза 0: Подготовка (Месяцы 1-3)
*   **Цель:** Создать фундамент и обучить команду.
*   **Бизнес-ценность:** Минимизация рисков старта, формирование ожиданий.
*   **Ключевые активности:**
    1.  Аудит текущих источников данных (DWH, Legacy).
    2.  Выбор технологического стека (Kafka, S3, ClickHouse, dbt).
    3.  Обучение Data Engineers и Аналитиков новым инструментам.
    4.  Разработка стандартов (Data Contracts, Governance Policies).
    5.  Развертывание базовой инфраструктуры (Platform Team).

### Фаза 1: Пилот (Месяцы 4-9)
*   **Цель:** Запустить первый полноценный домен данных (Data Product).
*   **Домен:** **Финтех (Кредитование)** — наиболее критичный к скорости и качеству данных.
*   **Бизнес-ценность:** Ускорение скоринга, возможность выдавать кредиты за минуты.
*   **Ключевые активности:**
    1.  Формирование первой кросс-функциональной команды домена.
    2.  Создание пайплайна загрузки событий в Data Lake (Bronze).
    3.  Реализация витрин данных (Gold) для скоринга в ClickHouse.
    4.  Публикация первого Data Product в Каталоге Данных.
    5.  Настройка мониторинга качества данных (Data Quality).

### Фаза 2: Масштабирование (Месяцы 10-24)
*   **Цель:** Подключить основные бизнес-домены к платформе.
*   **Домены:** **Медицина (ЭМК, Диагностика)** и **Персонал/Клиники**.
*   **Бизнес-ценность:** Единый профиль пациента (360 view), аналитика загрузки врачей.
*   **Ключевые активности:**
    1.  Онбординг новых команд в Data Mesh.
    2.  Развитие Портала Самообслуживания (Self-Service Data Platform) для снижения когнитивной нагрузки на команды.
    3.  Внедрение Federated Computational Governance (автоматическая проверка политик).
    4.  Постепенный вывод из эксплуатации старых отчетов в DWH.

### Фаза 3: Зрелость и Инновации (Месяцы 25-36)
*   **Цель:** Использование данных для создания новых продуктов (AI/ML).
*   **Домен:** **ИИ и Предиктивная аналитика**.
*   **Бизнес-ценность:** Персонализированная медицина, раннее выявление заболеваний.
*   **Ключевые активности:**
    1.  Интеграция Feature Store (MLflow) в Data Mesh.
    2.  Автоматизация MLOps процессов.
    3.  Монетизация обезличенных данных (Data as a Service) для внешних партнеров.
    4.  Полный отказ от Legacy DWH.

## 2. Ключевые Роли и Обязанности

| Роль | Зона ответственности | В каком домене |
|---|---|---|
| **Data Product Owner** | Отвечает за ценность продукта данных, бэклог, SLA и удовлетворенность потребителей. | В каждом бизнес-домене (Финтех, Медицина) |
| **Data Engineer** | Реализует ETL/ELT пайплайны, отвечает за качество кода и производительность обработки данных. | В каждом бизнес-домене |
| **Data Analyst / BI** | Строит отчеты, дашборды, проверяет гипотезы на основе витрин данных. | В каждом бизнес-домене |
| **Platform Engineer** | Создает и поддерживает общую инфраструктуру (Kafka, K8s, CI/CD, Data Catalog), предоставляет сервисы "как платформу". | Data Platform Team (Центральная команда) |
| **Data Governance Lead** | Разрабатывает политики безопасности, стандарты качества и метаданных. | Data Governance Office (Центральная функция) |

## 3. Критерии Успеха (KPIs)
*   **Time-to-Insight:** Сокращение времени от возникновения события до появления в отчете с 24 часов (batch) до <5 минут (streaming).
*   **Data Quality Score:** % успешных проверок качества данных > 99%.
*   **Adoption Rate:** % аналитиков, использующих новый Портал Данных (цель > 80% к концу Фазы 2).
*   **Cost Efficiency:** Снижение стоимости хранения 1 ТБ данных за счет S3 Tiering.
